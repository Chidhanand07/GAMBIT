## Behaviour changes

- **Protected pages need a session Supabase can verify.** The old middleware accepted any cookie that decoded to an unexpired JWT, signed or not. A forged or unverifiable cookie now redirects to `/login`. An expired access token is refreshed with the refresh token; the old "expired under a minute ago is still fine" allowance is gone.
- **If Supabase Auth is unreachable**, protected pages redirect to `/login` instead of rendering (fail closed, F-024).
- **Faster API calls once asymmetric signing keys are enabled** in Supabase: one Auth round trip per request disappears. Until then nothing changes in speed or behaviour (the library falls back to asking Auth).
- **A signed-out or banned user's access token keeps working on read routes until it expires** (at most one hour) when keys are asymmetric. Profile edits ask Supabase Auth every time (F-025).
- `/api/debug/session` answers 404.
- No visual change is intended. Three UI libraries were bumped for React 19 (below).
