# ADR 0003 — Consolidate the stack from 19 to 13 PRs

- **Status:** accepted (PR 12)

## Context
The plan had 19 stacked PRs (00–18). During execution the owner asked for
fewer pending PRs and a faster finish.

## Options
1. Keep 19 small PRs, built strictly one after another.
2. Merge adjacent PRs that touch the same layer and build independent areas in
   parallel worktrees, then stack them.

## Decision
Option 2, giving 13 PRs:
- 04 = config/clients + repositories (old 04+05, separate commits)
- 05 = services (old 06+07)
- 06 = http + sockets + shim + dead-endpoint deletion (old 08+09)
- 07 = types + lib/chess (old 10); 08 = route handlers (old 11)
- 09 = game page (old 12+13)
- 10 = lobby, profile, analysis/Navbar/offline/result, remaining pages (old 14–16),
  built by four agents in parallel worktrees and cherry-picked
- 11 = engine (old 17); 12 = wrap-up (old 18)

Commit subjects created before the change still say `[NN/19]`; PR titles use
`[NN/13]`.

## Why
Each merged PR still keeps its parts in separate commits, so review stays
commit-by-commit. Parallel work touched disjoint files. The only shared files
were the lint baselines, regenerated by script on merge, and one README table,
merged as the union of both sides. All suites were re-run on the final stacked tip.
